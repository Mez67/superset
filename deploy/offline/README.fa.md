# نصب «داده‌نما» در محیط بدون اینترنت

این پوشه همه چیزهایی را دارد که برای اجرای داده‌نما (Superset سفارشی ما) روی سروری
بدون اینترنت لازم است. کار در دو مرحله انجام می‌شود:

1. **روی یک سیستم با اینترنت** (ویندوز با Docker Desktop): ساخت بسته، همراه با اسکن امنیتی
2. **روی سرور بدون اینترنت** (لینوکس یا ویندوز): بارگذاری و راه‌اندازی

## ۱. ساخت بسته (سیستم با اینترنت)

پیش‌نیاز: Docker Desktop در حال اجرا، Git، و حدود ۲۰ گیگابایت فضای خالی.

```powershell
git pull
powershell -ExecutionPolicy Bypass -File deploy\offline\build-bundle.ps1
```

اسکریپت به ترتیب این کارها را می‌کند (حدود ۳۰ تا ۶۰ دقیقه):

- ساخت ایمیج داده‌نما با ترجمه فارسی، ورود Active Directory و پیش‌بینی
- آزمودن ایمیج: بارگذاری `python-ldap`، `prophet`، ترجمه‌ها و لوگو
- دریافت ایمیج‌های PostgreSQL 17 و Redis 7
- اسکن امنیتی هر سه ایمیج (بخش ۴)
- ذخیره همه ایمیج‌ها در `images.tar` و ساختن فهرست اثرانگشت (SHA256) همه فایل‌ها

خروجی در `dist\danehnama-offline-<نسخه>` است. **کل این پوشه** را (با فلش، هارد یا هر
روشی که سازمان شما مجاز می‌داند) به سرور منتقل کنید.

## ۲. نصب روی سرور بدون اینترنت

پیش‌نیاز: Docker Engine با افزونه Compose (لینوکس) یا Docker Desktop (ویندوز)،
حداقل ۴ هسته CPU، ۸ گیگابایت RAM و ۳۰ گیگابایت دیسک.

**لینوکس:**
```bash
cd danehnama-offline-<نسخه>
sudo ./install.sh
```

**ویندوز:**
```powershell
cd danehnama-offline-<نسخه>
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

بار اول اسکریپت فایل `.env` را می‌سازد و متوقف می‌شود. همه مقدارهای `CHANGE_ME` را با
رمزهای طولانی و تصادفی عوض کنید. روی لینوکس با این دستور می‌توانید رمز بسازید:

```bash
openssl rand -base64 42
```

بعد اسکریپت را دوباره اجرا کنید. اسکریپت این کارها را انجام می‌دهد:

1. اثرانگشت همه فایل‌ها را با `SHA256SUMS.txt` مقایسه می‌کند. اگر حتی یک بایت در مسیر
   انتقال تغییر کرده باشد، نصب متوقف می‌شود.
2. ایمیج‌ها را بارگذاری می‌کند و شناسه هر کدام را با `IMAGE_IDS.txt` می‌سنجد.
3. پایگاه داده را می‌سازد، کاربر `admin` را با رمز `ADMIN_PASSWORD` ایجاد می‌کند و برنامه
   را روی درگاه `8088` بالا می‌آورد.

بعد از نصب، نشانی `http://<آی‌پی سرور>:8088` را باز کنید و با `admin` وارد شوید. رمز
admin را از منوی کاربر عوض کنید.

### تنظیمات

- **رمزها و درگاه:** در `.env`
- **زبان، تقویم، Active Directory و جاسازی:** در `config/superset_config_docker.py`. نمونه
  تنظیمات AD و جاسازی داخل همین فایل است؛ از حالت توضیح خارجشان کنید و مقدارها را پر کنید.

بعد از هر تغییر:

```bash
docker compose up -d --force-recreate
```

نکته‌های مهم:

- **`SUPERSET_SECRET_KEY` را بعد از اولین اجرا هرگز عوض نکنید.** رمز اتصال‌های پایگاه داده
  با آن رمزگذاری می‌شود. یک نسخه از آن را جای امن نگه دارید.
- برنامه هیچ درخواستی به اینترنت نمی‌فرستد. آمار ناشناس Superset (Scarf) هم در تنظیمات خاموش است.
- برای استفاده واقعی، جلوی آن یک nginx یا IIS با HTTPS بگذارید.

## ۳. به‌روزرسانی

بسته جدید را روی سیستم با اینترنت بسازید، به سرور ببرید و `install.sh` یا `install.ps1`
را از پوشه **جدید** اجرا کنید. اول فایل‌های `.env` و
`config/superset_config_docker.py` را از پوشه قبلی به پوشه جدید کپی کنید. داده‌ها در
volume‌های Docker می‌مانند. migration‌های پایگاه داده خودکار اجرا می‌شوند.

پشتیبان‌گیری قبل از هر به‌روزرسانی:

```bash
docker compose exec db pg_dump -U superset superset > backup-$(date +%F).sql
```

## ۴. اطمینان از سلامت ایمیج (اسکن امنیتی)

`build-bundle.ps1` قبل از ساختن بسته، چهار بررسی انجام می‌دهد. گزارش‌ها در پوشه
`reports` داخل بسته هستند:

| بررسی | ابزار | فایل گزارش |
|---|---|---|
| آسیب‌پذیری‌های شناخته‌شده (CVE) در سیستم‌عامل و کتابخانه‌های Python و Node | Trivy | `trivy-*.txt` و `trivy-*.json` |
| رمز، کلید یا توکن جاخوش‌کرده در ایمیج | Trivy (secret) | همان فایل‌ها |
| بدافزار در تک‌تک فایل‌های ایمیج داده‌نما | ClamAV | `clamav-superset.txt` |
| فهرست کامل اجزای نرم‌افزار (SBOM) برای ممیزی | Syft | `sbom-*.spdx.json` |

اگر ClamAV حتی یک فایل آلوده پیدا کند، اسکریپت متوقف می‌شود و بسته ساخته نمی‌شود.

### چطور گزارش‌ها را بخوانید
- **`clamav-superset.txt`:** باید `Infected files: 0` باشد.
- **`trivy-*.txt`:** فهرست CVE‌ها با شدت. بیشترشان در کتابخانه‌های سیستم‌عامل پایه هستند
  و در همه ایمیج‌های رسمی هم دیده می‌شوند. مهم آن‌هایی است که شدت `CRITICAL` دارند و
  ستون `Fixed Version` پر است؛ یعنی نسخه اصلاح‌شده وجود دارد. اسکریپت در پایان تعداد
  CRITICAL‌ها را خلاصه می‌کند.
- **بخش Secrets در Trivy:** نباید چیزی جز کلیدهای نمونه کتابخانه‌ها (مثلاً در پوشه test
  پکیج‌ها) باشد.

### چرا به این ایمیج می‌شود اعتماد کرد
- **ساخته شدن از کد خودتان:** ایمیج روی سیستم خودتان و از همان commit‌ای ساخته می‌شود که در
  `SOURCE_COMMIT.txt` ثبت شده است.
- **وابستگی‌های قفل‌شده:** ایمیج‌های پایه Dockerfile با اثرانگشت (sha256) قفل شده‌اند. کتابخانه‌های
  JavaScript با `package-lock.json` و هش یکپارچگی، و کتابخانه‌های Python با نسخه‌های ثابت
  `requirements/base.txt` نصب می‌شوند. چیزی بدون نسخه مشخص وارد ایمیج نمی‌شود.
- **تفاوت با Superset رسمی:** همه تغییرات ما در commit‌های جدا روی شاخه هستند و
  می‌توانید فهرستشان را ببینید:
  ```bash
  git fetch https://github.com/apache/superset.git master
  git diff --stat FETCH_HEAD...HEAD
  ```
- **دست‌نخوردن در مسیر:** نصب‌کننده اثرانگشت همه فایل‌ها و شناسه هر ایمیج را می‌سنجد.

### اسکن دوباره روی سرور (اختیاری)
اگر سازمان شما آنتی‌ویروس یا اسکنر تأییدشده دارد، `images.tar` را قبل از نصب با آن هم
اسکن کنید. بعد از نصب هم می‌توانید فایل‌های ایمیج را بیرون بکشید و با همان ابزار اسکن کنید:

```bash
docker export $(docker create danehnama/superset:<نسخه>) -o rootfs.tar
```
